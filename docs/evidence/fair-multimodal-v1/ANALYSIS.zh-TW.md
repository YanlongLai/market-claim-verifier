# 公平多模態測試：閱讀結果與後續改進

本文件說明如何解讀這輪測試；所有數字以[完整結果](REPORT.md)、[逐項 JSON](summary.json)與[費用稽核](audit.json)為準。[原始輸入與事先固定的規則](../../../eval/multimodal-v1/README.md)在付費執行前已提交。

## 這次比較了什麼

- 開發組是 Apple、Nvidia，每家公司四個主張，測試查核階段的預設／低推理兩個設定。短文件抽取仍沿用原 repo 的預設推理，並沒有自動繼承查核的 low 設定；完整 request 可查證。依正確數、錯誤支持數、成本選擇；三家最後都選到低推理。這是「兩個開發設定中較好的選擇」，不是宣稱已找到模型所有可能配置中的最佳值。
- 正式組是 Amazon、Intel、Tesla、Microsoft、Alphabet、Meta。每家公司四個主張：兩個真實數值、一個故意改錯的淨利，以及一個截至日尚無證據的未來期間。
- 同一內容轉成 TXT、Markdown、原生文字 PDF、PNG、JPEG、WebP、WAV、MP3、MP4。**只有 24 個獨立的基礎主張、六個公司群組**；格式轉換不能變成 216 個獨立題目來縮小誤差。
- 三家使用同一份檔案、同一份截至 2026-10-30 的 SEC 快照、固定輸出上限及評分規則。Meta 是 Muse Spark 1.3；Baseten、Fireworks 是指定的 Muse Spark Open 端點，因此結果同時包含模型與服務差異。這是 repo 已整合的 Muse 模型比較，不是各平台所有模型的排行榜。

## 為什麼分成兩種比較

**產品流程測試**先共用並凍結 Meta OCR／ASR 結果，再讓三家查核完全相同的文字。這能比較「這個產品搭配哪個文字查核平台」，不能證明另外兩家原生處理聲音或影片的能力。

**原生圖片測試**則把相同 PNG、JPEG、WebP 直接送給各家的圖片端點。數字保存率、文字編輯率只是辨識診斷，不是財務判斷正確率，也不是圖片真偽檢查。這些原生圖片呼叫只屬於測試工具；產品 `ingest` 仍共用 Meta OCR，並未因此新增另一條原生圖片查核流程。原生聲音／影片端點本輪沒有測試，應標示未測，不應寫成不支援。

三張真實 Tesla 投影片另列診斷。它們沒有完整、獨立人工審核的標準答案，因此不混入準確率分母。控制組的音訊是 eSpeak 合成語音，影片是靜態卡片加語音，不能推論到真實長時間法說會、快速變換的畫面或說話者身分辨識。

## 準確率、速度與價格怎麼看

1. 嚴格正確率包含所有預先列出的主張；漏抽、對不到公司／指標／期間、未完成與判錯都會扣分。不能只對成功抽出的句子計算準確率。
2. 「錯誤支持」另外顯示：錯誤或缺乏證據的主張被判為 supported，與保守拒答是不同問題。拒答仍會在應有答案的題目扣分。
3. 相同文字的查核結果可以用雜湊快取重用，但每次重用都標示來源。它不是新的模型實驗，快取命中也不拿來宣稱 API 比較快。
4. 三家的實際使用／保留額包含開發、失敗、診斷與原生圖片呼叫；共用 OCR／ASR 費用全記在 Meta。每份文件的工作流程估算成本另列，不能把它們全部相加再當成實際帳單。
5. 延遲只反映這次固定並行度與網路下的觀察，不是服務 SLA。六個公司群組的信賴區間也很不穩定，不能推出全面的供應商排名。這是單次實驗，尚未量測重複推理的波動；公司群組 bootstrap 也不涵蓋模型隨機性。高分主要反映清晰的單一數值題，不代表複雜金融敘事、因果解釋或預測的正確率。
6. 每平台授權上限是 $40，呼叫准入上限設為 $35 留下結算餘裕。這是支出上限，不是必須花完的額度；ledger 是估算／保留額，尚未與供應商帳單核銷。

## 已找到的改善方向

[具體案例與原始證據](OBSERVATIONS.md)顯示：文字轉錄正確仍可能在後續模型輸出結構與總判定規則之間失敗。下一版應明確區分「可由 SEC 身分與期間欄位驗證的 metadata」和真正需要額外證據的非數字主張。必須同時測試錯公司、錯期間與不可驗證的修飾語，不能為了提高分數而忽略所有未知子主張。

後續優先順序：

1. 保留此輪結果，針對失敗類型建立回歸測試；改善版本使用新的、未調參的測試組。
2. 增加獨立人工標註的真實表格、簡報與法說會片段，涵蓋 GAAP／non-GAAP、單位、季度／累計與缺漏資訊；公開標註分歧。
3. 以現有多文件 queue 加入股票代號與多檔上傳介面，顯示逐檔進度、費用、未完成部分與可下載報告。
4. 加入可選 AI 敘述摘要，但每一項財務敘述必須附已驗證來源 ID，所有數字必須通過結構化結果校驗，失敗時保留現有確定性摘要。
5. 再擴充原生聲音／影片適配器、長影音續跑與供應商原生 Batch。新增能力各自測試，不能用同模型名稱推定端點能力。

## 同一股票多文件

[現有使用方式](../../STOCK_REVIEW.md)已提供 `review-stock` 批次查核與 `stock-summary` 無新增 API 費用的彙整。報告保留每份文件、原文位置、數值修正、其他公司與未指派公司的內容，以及未完成項目。

這份摘要回答「你提供的文件有哪些主張、哪些有證據、哪些需要修正／補證」，不直接產生買賣評級或未來股價預測。上傳文件目前是被查核的內容，不能自動變成可覆蓋 SEC 的權威證據。網頁拖拉介面與 AI 敘述摘要尚未完成，已列入後續計畫。

[離線重算與重用指南](REUSE.md)說明如何直接使用 repo 裡的 input、output、原始回應與 ledger；重算報告不會再呼叫 OCR、ASR 或模型。

## 本輪結論與已完成的修正

正式九種格式中，Fireworks 每種皆為 24/24；Baseten 除 WAV 23/24 外皆為 24/24；Meta 介於 MP3 的 14/24 與 PNG 的 24/24。這表示在這份小型控制組與固定流程中，Fireworks 的完整度最高，不能據此宣稱所有金融資料都能百分之百驗證。三家沒有觀察到錯誤支持，但底層負面／證據不足題目只有 12 個，並非零風險證明。

每家 42 個非快取文字工作（抽取加多次查核）的中位時間：Meta 123.222 秒、Baseten 25.635 秒、Fireworks 165.021 秒；不含共用 OCR／ASR。Baseten 在這次環境較快，Fireworks 完整率較高。Meta 的落差包含抽取未完成、額外子主張未驗證與保守拒答，不能直接歸因於聲音辨識品質。各平台原生 PNG、JPEG、WebP 都完成各 6/6 個控制圖片；數字 token 保存率皆為 72/72，但這項正規化指標不驗證正負號、單位綁定或表格語意。

真實 Tesla 三頁在原始流程中全部未產生可用主張，這個失敗已原樣保留。之後另開 [產品修正實驗](../stock-context-posthoc-2026-10-30/REPORT.md)：加入未經認證的股票代號提示、有限主張抽取及連續原文列引用。第一輪仍有四筆非連續引用被拒絕；第二輪保留八個主張，三筆有證據、五筆證據不足，圖表頁零主張仍標示未查核。[實際摘要](../stock-context-posthoc-2026-10-30/attempt-2/summary/stock-review.html)可以直接開啟。

這是已知失敗上的 Baseten 修正檢查，重用原有 Meta OCR，沒有重新估計三家準確率，也沒有改寫原始 benchmark。新增的股票提示不能覆蓋文件明示的其他公司。現金流指標與營運 KPI 的證據覆蓋仍不足；此輪也沒有修正 Meta 的未知子主張合併規則。

全部支出估算／保留額：Meta $4.23601935、Baseten $2.09934800、Fireworks $2.01364550。Baseten 包含另外兩輪合計 $0.14738175；每家皆低於 $40。費用不是帳戶剩餘 credit，也不是供應商最終帳單。[機器可讀總帳](task-spend.json)與兩套稽核分開保留。

已完成 CLI 多文件查核、可追溯摘要及 901 個產品測試；下一個產品優先項目是多檔上傳介面，再來才是有引用與數值校驗的 AI 敘述摘要。真實人工標註資料及現金流／營運指標覆蓋應同步擴充，使用新的保留測試組評估。
