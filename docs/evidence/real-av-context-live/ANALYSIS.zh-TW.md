# 補齊期間後的真實影音實際查核

三家各查核同樣六個已凍結的主張，沒有重跑語音辨識、OCR 或抽取。這是上一輪已知失敗的事後產品驗證，不是獨立準確率評測。[完整結果](REPORT.md) · [可讀報告](results.html) · [原始輸入與來源](cases.json)。

## 結果

| 平台 | 有證據支持 | 證據不足 | 執行失敗 |
| --- | ---: | ---: | ---: |
| Meta | 1 | 2 | 3 |
| Baseten | 5 | 1 | 0 |
| Fireworks | 5 | 1 | 0 |

Baseten 與 Fireworks 支持四項 GAAP 財務數值，以及營收／年增率主張。原本只是因表頭引用與期間不足而無法查核的主張，現在確實取得程式判定。以下列 Baseten 的有效檢查為例：

| 項目 | 原始主張 | 查得數值 | 判定依據 |
| --- | --- | --- | --- |
| 營收 | $92.3B | $92.279B | 符合原文四捨五入精度 |
| 淨利 | $36.6B | $36.629B | 符合原文四捨五入精度 |
| 稀釋 EPS | $4.92 | $4.92 | 金額一致 |
| 營業利益 | $45.9B | $45.915B | 符合原文四捨五入精度 |
| 營收年增率 | 19% | 約 18.8045% | 符合整數百分比精度 |

這些結果是有條件採用已檢視的 Microsoft FY2027 Q1 事件期間，不代表說話者身分已認證，也不保證整張表所有欄位或整段影片都正確。原文引用、補充期間和完整工具證據可分別追溯。

## 保守防護是否仍有效

未補上明確期間的 $4.89 調整後 EPS 對照案例，三家都在模型請求前由程式回傳 `missing_period`，新增 API 費用為零。沒有把它偷偷改成 GAAP $4.92，也沒有為了提高成功數而強制補期間。

Meta 的營收／年增率案例，兩項數值子檢查可對上，但另外的 release quote 檢查出現 issuer／metric／kind／unit／period mismatch，最後仍是證據不足。最終摘要遵守程式結果，沒有採用模型較強的結論。

Meta 的另外三項執行失敗是保存的 HTTP 500／InternalServerError；trace 中可見工具往返期間的失敗及重試。這不是三項財務判斷錯誤，也不能藉此推論模型的金融知識較差。沒有另開成功重跑來替換失敗紀錄。

## 預算與紀錄

以使用者最新回覆為準，本輪三家合計上限 $30，取代較早的每家 $30 說明，並繼續遵守先前各平台 credit 總額限制。此次實際執行仍維持每家 $2 上限；不會自動花掉剩餘授權。新增估算／保留額：Meta $0.30357855、Baseten $0.04467450、Fireworks $0.06691585，合計 $0.41516890。所有追蹤中的本次開發工作合計仍低於較嚴格的先前每家 $40 任務上限；不是帳戶剩餘 credit 或供應商最終帳單。

18 份結果與 53 次原始 API 請求／回應、工具呼叫、三家 ledger、原始模型說明及程式最終摘要均保留。錯誤、重試與沒有回報 usage 的保留額都計入支出。[機器結果與稽核](summary.json)可離線重算，不需要 API 金鑰。

## 下一步

2. 針對 Meta 的工具往返 HTTP 500 另作服務診斷；若重試，建立新 run，不能覆蓋本輪結果。
3. 為調整後 EPS／constant currency 補上可追溯的調節表與明確期間，再檢查聲音和畫面的口徑是否一致。
4. 用另一家公司、不同錄音與獨立標註的保留資料評估泛化效果。這六項已知案例以後只適合作回歸，不作盲測準確率。
